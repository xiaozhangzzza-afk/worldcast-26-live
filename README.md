# 足球预测大模型 V5.6.0

纯 HTML、CSS、JavaScript 的足球数据站，可直接部署到 GitHub Pages。V5.0 以英超、西甲、德甲、意甲、法甲为主内容，世界杯收纳为独立专题，并增强实时比分、事件时间轴和离线快照。

## 页面结构

- `index.html`：首页摘要、下一场焦点战、3 场焦点比赛和模型观察。
- `predictions.html`：全部比赛预测、日期/阶段筛选、比分分布和详情弹窗。
- `schedule.html`：五大联赛积分榜、球队未来比赛，以及世界杯赛程与阶段筛选。
- `teams.html`：球队数据库、球员档案、评分、风险标签和收藏。
- `about.html`：模型边界、数据来源、FAQ 和合规说明。

## 数据架构

- `assets/js/data-normalizer.js`：标准化世界杯数据；`assets/js/league-normalizer.js` 标准化五大联赛赛程、球队、比分、概率和事件时间轴。
- `assets/js/prediction-service.js`：只管理预测比分、备选比分、概率、信心和关键因素，不修改真实赛程或正式比分。
- `assets/js/data-service.js`：按月读取五大联赛赛程，页面可见时每 20 秒核验当月比分、每 5 分钟刷新完整赛程；进入详情时同步事件时间轴，并通过 `window.FM_STORE` 和 `fm:data-*` 事件供所有页面共享。
- `assets/data/snapshot.json`：世界杯固定快照；`assets/data/leagues-snapshot.json`：五大联赛最近可用快照。
- `assets/js/data.js`：仅保留模型观察和 FAQ 等静态展示配置，不承载真实赛程或比分频次。

真实事实层包含日期、队伍、场地、状态和正式比分；模型层包含预测比分、备选比分、胜平负概率、模型信心和因素。页面会明确区分两层。

## 数据源

五大联赛实时源：`https://site.web.api.espn.com/apis/site/v2/sports/soccer/{league}/scoreboard`

联赛标识：`eng.1`、`esp.1`、`ger.1`、`ita.1`、`fra.1`。世界杯专题优先读取本站 `data/live.json`，失败时使用旧仓库远程数据及发布快照。

实时源失败时比较发布快照和浏览器最近成功数据的时间，优先使用较新的版本；状态栏会明确显示实时、部分可用、快照或失败，不生成虚假赛程。

## 本地预览

不要直接双击 HTML 测试远程 `fetch`。在项目目录运行：

```bash
python -m http.server 8000
```

然后打开 <http://localhost:8000/>。

## GitHub Pages 部署

将项目根目录推送到 Pages 仓库的 `main` 分支，Pages 选择 `Deploy from a branch`，目录选择 `/ (root)`。当前公开地址为：

<https://xiaozhangzzza-afk.github.io/worldcast-26-live/>

发布新版本时同步更新 `service-worker.js` 的 `CACHE_NAME` 和 HTML 资源版本号（当前为 `5.6.0`）。首次打开新版本会执行一次旧缓存迁移；如仍看到旧页面，可使用强制刷新或在地址后添加 `?v=5.6.0`。

## 后续替换数据源

替换源时只需在 `data-service.js` 更新 URL，并在 `data-normalizer.js` 增加字段映射。保持 `FM_STORE` 和统一比赛/球队格式即可，不需要改动页面渲染层。

## 合规边界

模型演示，不构成投注、投资或财务建议。临场阵容、官方公告与实际赛果优先。正规观赛入口以页面列出的官方平台和资讯入口为准。
# V5.6.0：联赛与欧战、可核验预测档案

- `assets/js/competitions.js` 是五大联赛、欧冠、欧联杯、欧协联和世界杯归档的共享赛事目录。
- `assets/js/analytics.js` 与 `assets/data/prediction-history.json` 保存赛前预测，开赛冻结；不补录旧赛果。杯赛90分钟数据不完整时排除成绩结算。对比为次要折叠模块，模型参考值不是命中率。
- 真实比分频次仅覆盖当前加载的已完赛样本，非完整赛季。
- 完整赛程每5分钟刷新、实时比分每20秒核验；显示源更新时间与核验时间差异，失败保留并标明快照。公共接口可能延迟，不能保证逐秒直播。
- 欧战赛程可切换联赛阶段积分与淘汰赛；加时、点球与晋级信息分开，不由单场胜负推断晋级。
- 世界杯音乐恢复为10首小播放器，使用Apple官方试听及完整歌曲链接。尝试自动播放，浏览器阻止时显示点击播放；不提供盗版完整音频。
- 本地预览：在目录运行 `python -m http.server 8791`，访问 `http://localhost:8791`。GitHub Pages沿用主分支根目录部署。

## V5.6.0：统计补充、个性化与渐变层次

- `stat-model.js` 独立实现免费泊松基线：仅使用开赛前真实完赛样本，不生成对阵；每队至少3场、赛事至少20场有效样本。公开预测优先，缺失时补充比分/备选比分及胜平负，模型概率不是命中率。
- 半全场为同一泊松过程的九种联合结果，假设两半场各占50%强度；没有阵容、伤停、xG或回测校准，不冒充专家预测。完整参数与边界见模型说明页。
- 预测中心默认展示待赛，已完赛显示实际比分及真正冻结的赛前档案；缺失字段不反复显示“预测数据待更新”。
- `quality.js` 区分请求耗时、核验时间与提供方数据时间；源时间缺失时明示无法验证真实直播延迟，不用本机刷新时间冒充。
- `favorites.js` 跨联赛和欧战统一同一俱乐部收藏；首页“我的球队”显示下一场、近期赛果、积分排名。积分变化从设备首次观察后开始，不推断不存在的历史变化。
- 音乐连续播放官方试听歌单，保存跨页面歌曲及进度，可拖动进度及循环；页面切换可能短暂停顿，浏览器自动播放限制仍有效，不扩展受版权限制的单曲试听。
- `assets/css/product.css` 使用蓝、青绿、香槟金低饱和渐变；积分榜前三、关注球队、胜负列用颜色加文字区分，不暗示已经确定晋级或降级。
- 验证：`node scripts/test-analytics.mjs`、`node scripts/test-product.mjs`、`node scripts/audit-live.mjs`。线上定时任务为尽力调度，不能承诺精准每5分钟执行。
